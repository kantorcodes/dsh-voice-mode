# Issue #15 回复稿（交用户直发；自有 repo 回帖通道）

十项反馈全部处置完毕，按项交代（含没做的和为什么）。代码在本仓库 `main`，计划与审查全程留痕于 `docs/plan/issue-15-ux-feedback.md`，每条改动都过了「实现 → 四连验证 → 独立审查 → 反向断言实证」的门禁。

**① 打断吃句（朗读中说话，开头被吃）——已修复。**
根因是打断生效前的语音被丢。现在播放期会预录约 2 秒音频，打断生效时把「你开口前约 250ms」起的语音并回识别段——长句整段不丢。锚点锚在「检测请求的音频起点」而非发送时刻，弱网/慢识别下也不会切掉句首。另加了一条保护：如果打断后你只说了「嗯/对」这类附和词，它不会被当成消息发出去。外放且回声消除不了的环境若觉得抢救段有杂音，设置里可关「打断语音抢救」。

**② 运行中说话要排队十几秒——已修复。**
根因在宿主给插件的提交接口硬编码了「排队」。现在运行中直接走会话的插话通道（`steer`），下一个步骤边界就被消费，不用等任务结束；任何失败都会自动回退成原来的排队行为，不会更差、不会重发。

**③ 实时转写不进输入框——已修复。**
partial 实时写进草稿了，定稿时替换掉实时部分（不会重复）。唤醒待机时的字幕仍是「它听到了什么」的诊断反馈，不进草稿。

**④ 识别慢/以为卡死——感知面已修，速度本身取决于本机算力。**
final 请求超时从 10s 提到 25s（对齐宿主上限，慢定稿不再白白多重传一次）；定稿超过 2 秒状态条会显示「识别中… Ns」递增，看得见它在工作。「模型精度」开关的文案改成了「准确模式/快速模式」——关掉 SenseVoice 重译走快速模式（准确度略降），慢与快从此是明示的取舍。本地识别的绝对速度受 CPU 限制，这一项给的是确定性（不白等）和选择权（快/准二选一），不是加速。

**⑤ 同音字/错别字/标点——新增了可选的 LLM 纠错（默认关）。**
发送前对整条文本做一次「只改错别字/同音字/补标点，保持原意」的纠错，复用 dsh 已配置的模型（不引入新凭据）；失败/超时一律用原文，不阻断发送。默认关是因为它每条消息多一次约 1 秒等待——需要就开。纠错前后的对比确认 UI 没做（先交付价值，留待后续）。

**⑥ 真全双工（播放期持续识别）——没做，原因如实说。**
播放期持续识别会和「AI 自聊防护」结构性冲突（回声会被当成用户话），要做需要先重做回声隔离，是架构级改动。这一版给的是「打断抢救」这个等价达成用户目标的方案（你说的每一个字都完整进消息），而不是形式上的全双工。

**⑦ 调低静音阈值后长句被切碎——已修复。**
根因是「断句阈值」和「发送等待」共用了同一个值。现在发送等待固定 1.2 秒，静音阈值只管「多快算说完」——调低它只影响断句快慢，不再把长句在自然停顿处切成多条。

**⑧ 设置改了像没生效——已修复（文案+可见性）。**
生效时机改成四档如实描述（即时/下次识别/下一段话/下次进入语音模式），原来声称「即时生效」的好几项其实是下次进入才生效（那是文档 bug）。设置卡片顶部现在会列出「已保存但未生效」的项和它们**当前实际生效的值**。另：静音阈值的「真热生效」经核实是伪需求（端点判定本来就在下一段话生效），没有做。

**⑨ 静默故障无头——已加提示与诊断。**
识别/打断检测通道连续失败、状态同步断连时状态条会有提示（可自愈的瞬时失败不打扰）；新增「复制诊断」按钮，一键复制版本/运行状态/设置快照/阶段耗时——**不含任何转写原文**（隐私口径）。仍有四条静默路径本期没做（定稿空返回、VAD 模型下载失败、SenseVoice 降级、TTS 队列溢出），前两条已有兜底反馈，如实登记。

**⑩ 版本兼容——已验证并留痕。**
0.2.1-rc.2（0.2.1 正式版候选）全链路冒烟通过；0.2.1-alpha.5 的设置卡片探针在本机稳定失败，但用**未经本次改动的发布包 0.7.25 做对照同样失败**——实证是环境/探针问题不是插件回归（记录在 compat-contract §20）。桌面端真 Electron 冒烟本机跑不了（无桌面环境），已列为待办，需要时在 Windows 侧补跑。
